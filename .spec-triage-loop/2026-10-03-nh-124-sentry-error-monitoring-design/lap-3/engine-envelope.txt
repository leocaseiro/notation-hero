[P1] Section: §5 Setup, steps 3 and 6 (Allowed Domains) — The day the site moves to its own domain, Sentry silently throws away every report (adversarial, product-lens (+1 anchor), confidence 100)
  Recommendation: Apply
  Consequence if unchanged: Once the site answers on its planned brand domain, every error report and every visit ping from there is discarded, no alert fires, and the empty issue list looks like a healthy site.
  Change: Let step 3 allow the brand domain as well as today's production host, either listed now or added by a stated step before the new domain serves visitors, and run the step-6 check on a listed domain.
  Basis: Allowed Domains (the project setting step 3 narrows from `*`) rejects any report whose page origin is not on the list, and Sentry shows the rejections only as "Disallowed Domain" on its Stats page. The repository already lists the domain move as separate work.

[P2] Section: §4 Releases, environments and source maps (the token check); §1 New files; §6 Testing — The check that guards the Sentry token skips the page files browsers actually download (security-lens, adversarial (+1 anchor), confidence 100)
  Recommendation: Apply
  Consequence if unchanged: A later change that renders the token into a page would ship it to every visitor while the build stays green.
  Change: Walk the prerendered page files, and the public folder, as well as the script folder, and correct the sentence that says only public variables can reach the browser.
  Basis: A static page's HTML and its data payload are written under the build's server folder, not under `.next/static`, and both are sent to browsers. Only browser JavaScript is limited to `NEXT_PUBLIC_` variables; a server component can render any variable into a page.

[P2] Section: §2.4 Every handled failure (E204 counts visible time only); §6 Testing (the font clock) — One music-font failure sends two unhandled errors, and the second can repeat (design-lens, confidence 75)
  Recommendation: Apply
  Consequence if unchanged: A visitor whose music font fails to download sends a font-failure error and, a minute later, a false "the font never arrived" error; the owner gets two issue emails, and the visitor's banner changes its words.
  Change: End the font clock for good at the first of three events — a finished render, the font-failure report, or the timeout report itself — and test both new cases.
  Basis: The font-failure path does not stop the 60-second clock, and a failed download never finishes a render. Once the timeout has fired, nothing in the text stops a later tab switch from starting it again.
