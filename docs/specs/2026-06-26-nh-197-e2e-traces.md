# NH-197 — Playwright e2e lane + traces/HTML report in CI

- **Ticket:** [NH-197](https://leocaseiro.atlassian.net/browse/NH-197) (Story, parent epic NH-176 Foundation & CI/CD)
- **Date:** 2026-06-26
- **Status:** Design — reviewed via ce-doc-review (6 personas) 2026-06-26; pending implementation plan
- **Author:** Leo (with Claude)

## Goal

Make end-to-end (e2e) failures debuggable from CI, not just readable as a red log. Capture Playwright **traces** (the interactive timeline: DOM snapshots, network, console, action-by-action) plus the **HTML report**, and upload them as CI artifacts so a failed run can be replayed locally with `npx playwright show-trace`.

This ticket **includes standing up the e2e lane itself** — no e2e lane exists today (Playwright only drives visual-regression `*.vr.ts` and accessibility `*.a11y.ts` against Storybook). So this work stands up the lane first, then wires traces into it.

## Why — this is foundation, not this test

The point of NH-197 is the **reusable e2e foundation**, not the placeholder smoke test passing. When a real feature is built later, this lane is the harness that lets an agent (or Leo) **verify the feature actually works in a real browser — replayable via traces — instead of asserting success from unit tests or guesswork**. The placeholder smoke test exists to establish the reusable pattern (navigate → mock the API → assert rendered data → clean boot) that future feature tests copy. This is consistent with the project's "foundation = real infrastructure, placeholder content" and "well-architected even at tiny scale" principles.

## Scope

**In scope**

- A new e2e lane: a dedicated Playwright config, an `e2e/` test dir, and a placeholder smoke test that doubles as the reusable template.
- An MSW (Mock Service Worker) mock layer — chosen as the durable foundation mock layer for future feature tests (see D2-mock).
- A new blocking CI job that runs the lane and uploads traces + the HTML report (with `if: !cancelled()`).
- Trace + HTML-report configuration.
- Docs: `AGENTS.md` and `client/README.md`.

**Out of scope (deferred)**

- Adding traces/HTML report to the existing VR/a11y lanes (possible later follow-up; this ticket is e2e-only).
- Migrating the existing Vitest unit tests off `vi.stubGlobal('fetch')` onto MSW (the MSW foundation makes this possible later, but it is not part of this ticket).
- The shared oRPC contract package (oRPC Phase 2) and contract-typed fixtures — see "Contract-fidelity path".
- Playwright CI sharding (single shard is plenty for a smoke test; the ticket lists it only as "consider").

## Design

### File layout (all under `client/`)

```
client/
  playwright.config.ts            # EXISTING — VR + a11y vs Storybook (unchanged)
  playwright.e2e.config.ts        # NEW — e2e vs the built app
  e2e/
    smoke.e2e.ts                  # NEW — placeholder smoke test (the reusable template)
    mocks/
      handlers.ts                 # NEW — MSW request handlers (typed)
```

**Layout-guard & Vitest compatibility (verified):**

- `tooling/check-layout.sh` Rule 1 bans `__tests__/`, `__mocks__/`, `stories/` dirs — `e2e/` and `e2e/mocks/` are fine.
- Rule 3 (co-located source sibling) only fires on `*.test.*` / `*.spec.*`. The `*.e2e.ts` suffix sidesteps it (the same trick `*.vr.ts` uses).
- Vitest only matches `src/**/*.{test,spec}.{ts,tsx}` (`client/vite.config.ts`), so files under `client/e2e/` are auto-excluded from `vitest run`. No Vitest config change needed.
- `client/.gitignore` already ignores `test-results` and `playwright-report`. No change needed.

### `playwright.e2e.config.ts`

```ts
import { defineConfig, devices } from "@playwright/test";

export default defineConfig({
  testDir: "./e2e",
  testMatch: "**/*.e2e.{ts,tsx}",
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  // Record a trace on the retry of a first-failed test (D5). With retries:2 in CI a failure
  // produces a replayable trace; the CI upload step uses `if: !cancelled()` so the trace is kept
  // even when the retry passes (a flaky run we still want to debug).
  use: {
    baseURL: "http://localhost:4173",
    trace: "on-first-retry",
    ...devices["Desktop Chrome"],
  },
  reporter: [["html"], ["list"]],
  // `vite preview` serves ONLY the static production build — it does NOT honor `server.proxy`
  // (that is dev-only). So `/api/*` has no backend here; MSW is the sole source of catalog data
  // (see MSW section). `--strictPort` fails loudly on a port collision instead of serving a stale
  // app. Timeout covers a cold `vite build` + preview boot on a CI runner.
  webServer: {
    command: "pnpm build && pnpm preview --port 4173 --strictPort",
    url: "http://localhost:4173",
    reuseExistingServer: !process.env.CI,
    timeout: 180_000,
  },
});
```

> The `build` CI job and this webServer both run `vite build` — they run in parallel jobs, so the cost is compute minutes, not wall-clock. A later optimization could split `pnpm build` into an explicit CI step and reduce the webServer command to `pnpm preview` only; not needed now.

### MSW mock layer

`client/e2e/mocks/handlers.ts` defines request handlers. The response is typed against the catalog shape the app expects (today the hand-synced `CatalogResponse` mirrored from `server/src/modules/catalog/catalog.controller.ts`; **Phase 2:** swap the type to `InferRouterOutputs<typeof contract>['catalog']['list']`).

```ts
import { http, HttpResponse } from "msw";

// Mirrors client/src/components/About.tsx's CatalogResponse (hand-synced, Phase 1).
// Phase 2: type this against the shared oRPC contract via InferRouterOutputs.
interface CatalogPlayable {
  id: string;
  title: string;
  kind: "song" | "pattern" | "lesson";
  difficulty: string;
}
interface CatalogResponse {
  items: CatalogPlayable[];
  count: number;
}

const catalog: CatalogResponse = {
  count: 1,
  items: [
    {
      id: "single-stroke-roll",
      title: "Single Stroke Roll",
      kind: "pattern",
      difficulty: "Debut",
    },
  ],
};

// Wildcard origin (`*/api/catalog`) so matching does NOT depend on referer-based relative-URL
// resolution — robust regardless of how the request URL is formed.
export const handlers = [
  http.get("*/api/catalog", () => HttpResponse.json(catalog)),
];
```

The handlers are applied inside the e2e tests via `@msw/playwright`, which intercepts through Playwright's network layer (`context.route` — confirmed by reading the package source; no service-worker script in the app bundle). The fixture is configured with **`onUnhandledRequest: 'error'`** so that if an `/api/*` call ever escapes the mock (e.g. a handler mismatch), the test **fails loudly at the network layer** instead of silently rendering the app's "Could not reach the API" error state and surfacing as a confusing assertion failure.

> **Implementation note:** `@msw/playwright` is at v0.6.7 (pre-1.0). Confirm the exact fixture API against the installed package's types/README during implementation (the verified shape is `defineNetworkFixture({ context, handlers })` + a Playwright `test.extend`). The handler definitions above use the stable MSW v2 `http`/`HttpResponse` API. Also confirm `skipAssetRequests` (defaults true) does not bypass `/api/catalog` — it is extensionless so it is treated as a normal request, not an asset.

### Smoke test — `client/e2e/smoke.e2e.ts` (the reusable template)

Client-only journey that demonstrates the pattern future feature tests will copy:

1. Load `/` → assert the Home heading renders ("Notation Hero" / "Skeleton ready.").
2. **Navigate to `/about` by clicking the in-app `<Link>`** (exercises client-side routing — the e2e-only value jsdom unit tests cannot see; avoids depending on `vite preview`'s SPA deep-link fallback).
3. Assert the About heading renders **and** the MSW-mocked catalog item ("Single Stroke Roll") appears — the reusable "page → mocked API → rendered data" template.
4. Assert the production build **boots clean** — no console errors during the journey (catches bundling/runtime wiring failures unit tests miss).

### CI — new `e2e` job in `.github/workflows/ci.yml`

Modeled on the existing `a11y` job (ubuntu + on-demand Chromium install — e2e is not pixel-exact, so no Playwright container needed, unlike `vr`).

```yaml
e2e:
  needs: changes
  if: ${{ needs.changes.outputs.code == 'true' }}
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0 # v7.0.0
    - uses: ./.github/actions/setup-js
    - name: Install Playwright Chromium
      run: pnpm --filter @notation-hero/client exec playwright install --with-deps chromium
    - name: e2e tests (Playwright vs built app)
      run: pnpm --filter @notation-hero/client run test:e2e
    - name: Upload traces + HTML report
      # NOT `if: failure()` — that would drop the trace of a flaky-then-passed run (D5).
      if: ${{ !cancelled() }}
      uses: actions/upload-artifact@<resolve-to-current-v4-SHA-at-impl> # v4
      with:
        name: playwright-e2e-report
        path: |
          client/playwright-report/
          client/test-results/
        retention-days: 7
        if-no-files-found: ignore
```

**Required implementation details:**

1. **Pin `actions/upload-artifact` to its current v4 commit SHA** (the repo pins every action by SHA — never ship the `<resolve-…>` placeholder or a mutable `@v4` tag).
2. **Permissions:** the workflow declares `permissions: contents: read`. `actions/upload-artifact@v4` normally uploads fine under that. Verify at implementation; **if** the upload step is denied, add a **job-scoped** block to the `e2e` job only (`permissions: { contents: read, actions: write }`) — do NOT elevate at the workflow level (least-privilege; other jobs must stay `contents: read`).
3. **`ci-green` registration — three edits**, or the gate is hollow:
   - add `e2e` to the `ci-green` job's `needs:` list;
   - add `e2e="${{ needs.e2e.result }}"` in the variable block;
   - add `e2e:$e2e` to the `for job in …` verification loop.
4. **Escape hatch (D3):** if the lane proves flaky and blocks unrelated PRs, the unblock is a one-line revert of the three `ci-green` edits above (job keeps running, just stops gating). Record this in the PR description so the unblock is a known 30-second operation.

## Acceptance criteria

- [ ] `playwright.e2e.config.ts` sets `trace: 'on-first-retry'` and `reporter: [['html'], ['list']]`.
- [ ] A client-only smoke test runs against the built app (`vite preview`) with `/api/catalog` mocked by MSW; it asserts client-side routing (`/` → `/about` via in-app link), the mocked catalog item, and a clean console boot.
- [ ] MSW fixture uses `onUnhandledRequest: 'error'` so a mock miss fails loudly.
- [ ] CI `e2e` job runs the lane, is registered in `ci-green` (blocks merge) via the three-edit wiring, and uploads `client/playwright-report/` + `client/test-results/` with `if: ${{ !cancelled() }}` and 7-day retention; `upload-artifact` is SHA-pinned.
- [ ] `npx playwright show-trace` is documented in `AGENTS.md` / `client/README.md`.
- [ ] `pnpm run lint`, `typecheck`, `test`, `build`, and the new `test:e2e` all pass locally and in CI.

## Verification plan

1. `pnpm --filter @notation-hero/client run test:e2e` passes locally (build → preview → smoke green).
2. Force a failure (wrong assertion) → confirm a trace is produced under `client/test-results/` and `npx playwright show-trace` opens the timeline.
3. Temporarily break the MSW handler → confirm `onUnhandledRequest: 'error'` makes the test fail at the network layer (loud), not as a vague missing-text assertion.
4. Push a branch → confirm the `e2e` job runs, gates `ci-green`, and that a deliberately-failing run uploads the `playwright-e2e-report` artifact. Confirm the upload also fires on a forced flaky-then-passed run (`if: !cancelled()`).
5. Revert the forced changes → green.

## Risks & caveats

- **`@msw/playwright` is pre-1.0 (v0.6.7).** Official mswjs org, last published 2026-04. Low risk for the foundation; pin the version. **Before bumping it past v0.6.7, manually review the changelog/npm diff** — osv-scanner advisory lag is longer on pre-1.0 packages. Fallback if it misbehaves: community `playwright-msw`, or plain Playwright `page.route`.
- **Trace data sensitivity (future).** Traces capture DOM snapshots, network bodies, and console output. Today that is placeholder data only. **When real user data (auth tokens, PII) flows through the e2e lane, add a guardrail** — keep MSW mocks so no real credentials reach the runner, or restrict artifact access — before the first feature that introduces auth. The artifact pipeline established here will otherwise be inherited unchanged.
- **The e2e gate asserts the mock, not the live server.** A green e2e check does **not** prove client/server contract alignment — the mock is hand-synced (Phase 1) and can drift from the real controller while the test still passes. That guarantee arrives only with the Phase-2 `InferRouterOutputs` typing (D4).
- **`@playwright/test` version is now load-bearing in three spots** — the root dep, the `vr` job's container tag (`mcr.microsoft.com/playwright:v1.61.1-noble`), and the `e2e` job's Chromium install. Bump them together.
- **Two Playwright configs, separate jobs** — running e2e (own config, Vite preview) alongside VR/a11y (existing config, Storybook) does NOT double the Storybook boot; they target different servers in different CI jobs.

## Contract-fidelity path (oRPC Phase 2 — reference, not this ticket)

When the shared oRPC contract package lands, replace the hand-written `CatalogResponse` in the MSW handler with the contract-inferred type:

```ts
import type { InferRouterOutputs } from "@orpc/server";
type CatalogResponse = InferRouterOutputs<typeof contract>["catalog"]["list"];
```

This makes the mock **compile-time faithful** to the real API — the guarantee a tool like Specmatic provides, but native to the TypeScript stack with zero added infra. OpenAPI-based contract testing (oRPC can emit OpenAPI via `@orpc/openapi`, then layer Prism/Specmatic) only becomes worthwhile if a **non-TypeScript or external consumer** appears. Until then, MSW + `InferRouterOutputs`-typed handlers is the end state.

Phase-2 pointers banked from research: canonical oRPC docs are at **orpc.dev**; pin the stable `@orpc/*` v1 line (currently 1.14.6) and note `@orpc/nest` is currently steered toward a v2 beta — decide deliberately.
