# NH-197 — Playwright e2e lane + traces/HTML report in CI

- **Ticket:** [NH-197](https://leocaseiro.atlassian.net/browse/NH-197) (Story, parent epic NH-176 Foundation & CI/CD)
- **Date:** 2026-06-26
- **Status:** Design — pending review
- **Author:** Leo (with Claude)

## Goal

Make end-to-end (e2e) failures debuggable from CI, not just readable as a red log. Capture Playwright **traces** (the interactive timeline: DOM snapshots, network, console, action-by-action) plus the **HTML report**, and upload them as CI artifacts so a failed run can be replayed locally with `npx playwright show-trace`.

The ticket is scoped "when the e2e lane lands" — but no e2e lane exists today (Playwright only drives visual-regression `*.vr.ts` and accessibility `*.a11y.ts` against Storybook). So this work **stands up the e2e lane first**, then wires traces into it.

## Why

Leo wants to debug e2e failures from the pipeline. The Playwright trace timeline is the tool for that. Standing up the lane with a placeholder smoke test gives every future feature a debuggable e2e path from day one, consistent with the "foundation = real infrastructure, placeholder content" rule.

## Scope

**In scope**

- A new e2e lane: a dedicated Playwright config, an `e2e/` test dir, and a placeholder smoke test.
- An MSW (Mock Service Worker) mock layer for the e2e lane's API calls.
- A new CI job that runs the lane, blocks merge, and uploads traces + the HTML report on failure.
- Trace + HTML-report configuration.
- Docs: `AGENTS.md` and `client/README.md`.

**Out of scope (deferred)**

- Adding traces/HTML report to the existing VR/a11y lanes (possible later follow-up; this ticket is e2e-only).
- Migrating the existing Vitest unit tests off `vi.stubGlobal('fetch')` onto MSW.
- The shared oRPC contract package (oRPC Phase 2) and contract-typed fixtures — see "Contract-fidelity path".
- Playwright CI sharding (single shard is plenty for a smoke test; the ticket lists it only as "consider").

## Design

### File layout (all under `client/`)

```
client/
  playwright.config.ts            # EXISTING — VR + a11y vs Storybook (unchanged)
  playwright.e2e.config.ts        # NEW — e2e vs the built app
  e2e/
    smoke.e2e.ts                  # NEW — placeholder smoke test
    mocks/
      handlers.ts                 # NEW — MSW request handlers (typed)
```

**Layout-guard & Vitest compatibility (verified):**

- `tooling/check-layout.sh` Rule 1 bans `__tests__/`, `__mocks__/`, `stories/` dirs — `e2e/` and `e2e/mocks/` are fine.
- Rule 3 (co-located source sibling) only fires on `*.test.*` / `*.spec.*`. The `*.e2e.ts` suffix sidesteps it (the same trick `*.vr.ts` uses).
- Vitest only matches `src/**/*.{test,spec}.{ts,tsx}` (`client/vite.config.ts`), so files under `client/e2e/` are auto-excluded from `vitest run`. No Vitest config change needed.
- `client/.gitignore` already ignores `test-results` and `playwright-report`. No change needed.

### `playwright.e2e.config.ts`

```ts
import { defineConfig, devices } from "@playwright/test";

export default defineConfig({
  testDir: "./e2e",
  testMatch: "**/*.e2e.{ts,tsx}",
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  // Trace on the retry of a first-failed test — the ticket's requested mode. Combined with
  // retries:2 in CI, a flaky/real failure produces a replayable trace without tracing every run.
  use: {
    baseURL: "http://localhost:4173",
    trace: "on-first-retry",
    ...devices["Desktop Chrome"],
  },
  reporter: [["html"], ["list"]],
  // Build the SPA and serve it with `vite preview` (the production build, same as behind CloudFront).
  // Reused locally if already running; CI builds fresh.
  webServer: {
    command: "pnpm build && pnpm preview --port 4173",
    url: "http://localhost:4173",
    reuseExistingServer: !process.env.CI,
    timeout: 120_000,
  },
});
```

### MSW mock layer

`client/e2e/mocks/handlers.ts` defines request handlers. The response is typed against the catalog shape the app expects (today the hand-synced `CatalogResponse` mirrored from `server/src/modules/catalog/catalog.controller.ts`; **Phase 2:** swap the type to `InferRouterOutputs<typeof contract>['catalog']['list']`).

```ts
import { http, HttpResponse } from "msw";

// Mirrors client/src/components/About.tsx's CatalogResponse (hand-synced, Phase 1).
// Phase 2: type this against the shared oRPC contract via InferRouterOutputs.
interface CatalogPlayable {
  id: string;
  title: string;
  kind: "song" | "pattern" | "lesson";
  difficulty: string;
}
interface CatalogResponse {
  items: CatalogPlayable[];
  count: number;
}

const catalog: CatalogResponse = {
  count: 1,
  items: [
    {
      id: "single-stroke-roll",
      title: "Single Stroke Roll",
      kind: "pattern",
      difficulty: "Debut",
    },
  ],
};

export const handlers = [
  http.get("/api/catalog", () => HttpResponse.json(catalog)),
];
```

The handlers are applied inside the e2e tests via `@msw/playwright`, which runs MSW through Playwright's network interception (no service-worker script in the app bundle).

> **Implementation note:** `@msw/playwright` is at v0.6.7 (pre-1.0). The exact fixture/setup API (e.g. how the test imports the worker fixture and registers `handlers`) must be confirmed against the installed package's types/README during implementation. The handler definitions above use the stable MSW v2 `http`/`HttpResponse` API.

### Smoke test — `client/e2e/smoke.e2e.ts`

Client-only journey across the two existing routes:

1. Load `/` → assert the Home heading renders ("Notation Hero" / "Skeleton ready.").
2. Navigate to `/about` → assert the About heading renders **and** the MSW-mocked catalog item ("Single Stroke Roll") appears — proving the live-fetch + TanStack Query path works end-to-end with the mock in place.

### CI — new `e2e` job in `.github/workflows/ci.yml`

Modeled on the existing `a11y` job (ubuntu + on-demand Chromium install — e2e is not pixel-exact, so no Playwright container needed, unlike `vr`).

```yaml
e2e:
  needs: changes
  if: ${{ needs.changes.outputs.code == 'true' }}
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0 # v7.0.0
    - uses: ./.github/actions/setup-js
    - name: Install Playwright Chromium
      run: pnpm --filter @notation-hero/client exec playwright install --with-deps chromium
    - name: e2e tests (Playwright vs built app)
      run: pnpm --filter @notation-hero/client run test:e2e
    - name: Upload traces + HTML report on failure
      if: failure()
      uses: actions/upload-artifact@<pinned-sha> # v4
      with:
        name: playwright-e2e-report
        path: |
          client/playwright-report/
          client/test-results/
        retention-days: 7
```

**`ci-green` registration (required):** add `e2e` to the `ci-green` job's `needs:` list and to its result-verification loop (`e2e:$e2e`), so the gate actually enforces it. Without this the job runs but does not block merge.

## Verification plan

1. `pnpm --filter @notation-hero/client run test:e2e` passes locally (build → preview → smoke green).
2. Force a failure (e.g. a wrong assertion) → confirm a trace is produced under `client/test-results/` and `npx playwright show-trace` opens the timeline.
3. Push a branch → confirm the `e2e` job runs, gates `ci-green`, and that a deliberately-failing run uploads the `playwright-e2e-report` artifact.
4. Revert the forced failure → green.

## Risks & caveats

- **`@msw/playwright` is pre-1.0 (v0.6.7).** Official mswjs org, last published 2026-04. Low risk for a single smoke test; pin the version. Fallback if it misbehaves: the community `playwright-msw`, or plain Playwright `page.route` (the originally-recommended zero-dep path).
- **`@msw/playwright` exact API unverified at design time** — confirm the fixture/setup surface against v0.6.7 during implementation.
- **CI double-build** — the `build` job and the e2e `webServer` both run `vite build`. Acceptable cost for a smoke test; can be optimized later (artifact reuse) if it matters.

## Contract-fidelity path (oRPC Phase 2 — reference, not this ticket)

When the shared oRPC contract package lands, replace the hand-written `CatalogResponse` in the MSW handler with the contract-inferred type:

```ts
import type { InferRouterOutputs } from "@orpc/server";
type CatalogResponse = InferRouterOutputs<typeof contract>["catalog"]["list"];
```

This makes the mock **compile-time faithful** to the real API — the guarantee a tool like Specmatic provides, but native to the TypeScript stack with zero added infra. OpenAPI-based contract testing (oRPC can emit OpenAPI via `@orpc/openapi`, then layer Prism/Specmatic) only becomes worthwhile if a **non-TypeScript or external consumer** appears. Until then, MSW + `InferRouterOutputs`-typed handlers is the end state.

Phase-2 pointers banked from research: canonical oRPC docs are at **orpc.dev**; pin the stable `@orpc/*` v1 line (currently 1.14.6) and note `@orpc/nest` is currently steered toward a v2 beta — decide deliberately.
