## Original F-list (detail below)

## Cheap wins (this PR or the immediate next)

- [ ] **F-1 — Add a client-side fetch timeout to `fetchCatalog`.**
  - _What's missing:_ `web/app/lib/catalog.ts` does a bare `fetch(...)` with no timeout.
  - _Why it matters:_ the deleted `web/app/lib/db.ts` bounded its Neon read with an 8 s
    `AbortSignal.timeout(8000)`, and spec §1 explicitly flagged that dropped timeout as a problem.
    Without it, a cold or hung Lambda holds the Vercel function until its platform limit instead of
    failing fast into `error.tsx`.
  - _How:_ add the signal to the fetch (existing tests still pass — they mock `fetch`):

    ```ts
    const response = await fetch(`${base}/api/catalog`, { signal: AbortSignal.timeout(8000) });
    ```

- [ ] **F-2 — Add Zod runtime validation of the catalog response.**
  - _What's missing:_ `fetchCatalog` trusts the JSON via `as CatalogResponse` — a compile-time cast,
    no runtime check.
  - _Why it matters:_ this is the spec §10 fast-follow. `web` (Vercel) and the server (AWS Lambda)
    deploy on **separate pipelines**, so a deploy-skew window (new web expecting `level` hitting an
    older server without it, or vice versa) would render `undefined` fields **silently** rather than
    failing loudly. Zod has no private-member / dual-package hazard, so the schema is safe to live in
    `shared/`.
  - _How:_ add a Zod schema alongside `shared/src/contracts/catalog.ts` and `parse()` the JSON inside
    `fetchCatalog` (derive the TS types from the schema so there is one source of truth).

## Ship with the admin / CMS work

- [ ] **F-5 — Secured `revalidateTag('catalog')` route + admin publish/refresh button.**
  - _What:_ an on-demand cache purge so an admin can force-refresh the catalog instead of waiting out
    the `cacheLife('days')` window.
  - _Why:_ the `cacheTag('catalog')` hook is already wired for exactly this; the endpoint + button need
    the admin UI, which is out of scope now. Documented ADR follow-up.

## Grounding / future

- [ ] **F-6 — Benchmark the catalog Lambda cold start** (Lambda init + Neon connect + query) and record
      the number in the ADR §6, so the "acceptable Lambda hop on a cache miss" claim is grounded in a real
      measurement rather than an estimate.

- [ ] **F-7 — Server-side filtering / search / pagination (NH-123).** Today the API returns the full
      curated list (≤ 50) pre-sorted and `web` caches it whole + sorts/filters client-side (TanStack). When
      real search is needed the API grows query params (`?search=&level=&page=&sort=`) and does the work
      DB-side; caching then shifts to per-key (cache the default page; short/no cache for high-cardinality
      searches). Path 2 is the right base — the query logic lives once in the server.

## Low / optional

- [ ] **F-3 — Harden the server ordering test.** The unit test asserts `orderBy` arity (2 columns), not
      the `asc` direction or the column identity (Drizzle's `asc()` returns opaque `SQL` objects that are
      awkward to assert at the unit level). The real ordering is currently guarded only by the **skipped**
      Neon integration block. Option: run that integration block in CI against a Neon branch, or snapshot
      `spies.orderBy.mock.calls[0]`.

- [ ] **F-4 — (optional) Move `@notation-hero/shared` to `devDependencies`** in `server/package.json`
      and `web/package.json` — it is type-only and build-erased, so it never ships at runtime. Harmless
      either way. Leave `transpilePackages: ['@notation-hero/shared']` in `web/next.config.ts` — it is a
      no-op today but correct forward-compat if `shared` ever exports a runtime value.

## 2026-07-22 — triage decisions (session)

Disposition of every queued item after the session that landed the approved code fixes on PR #140.

**Zod outcome: fell back to Option C.** The runtime `catalogResponseSchema` lives in
`web/app/lib/catalog.ts`, **not** `shared/`. The preferred Option B (schema in `shared/`) failed: the
web build (`pnpm --filter @notation-hero/web build`) cannot resolve a runtime **value** import from
`@notation-hero/shared` — Turbopack reports `Module not found: Can't resolve './contracts/catalog.js'`
on the `.js`-specifier re-export in `shared/src/index.ts` (the NH-284 failure), and the server needs
that same `.js` extension for its `nodenext` **type-only** import, so the specifier cannot simply be
changed. `shared/` therefore stays type-only; the local schema is bound to shared's `CatalogResponse`
via `satisfies z.ZodType<CatalogResponse>` so the two cannot drift. Promote it into `shared/` once
`shared/` emits a real JS build.

**Implemented in #140**

- **1** — 8s `AbortSignal.timeout` on the web→server fetch.
- **2** — server order test pinned to `asc(playable.level), asc(playable.title)` (deep-equal; verified
  a wrong-column swap now fails). Closes **F-3 / R-3**.
- **3** — a bad-shape response now throws into `error.tsx` instead of caching `undefined` (via the Zod
  parse). Closes **R-2 / R-7**.
