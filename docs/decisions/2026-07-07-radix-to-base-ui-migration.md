# ADR — Component library: Radix (`radix-ui` + `cmdk`) → Base UI (`@base-ui/react`)

- **Status:** ✅ Accepted 2026-07-07
- **Date:** 2026-07-07
- **Driver / Approver:** leocaseiro
- **Ticket:** [NH-254](https://leocaseiro.atlassian.net/browse/NH-254) (catalog search + filter-row UI, PR [#99](https://github.com/leocaseiro/notation-hero/pull/99)) — this pilot; also touches [NH-268](https://leocaseiro.atlassian.net/browse/NH-268) (Storybook-as-living-docs, folded in) and freezes the in-flight NH-262 (#101/#109/#112) and NH-264 primitive PRs pending redirect.
- **Evidence:** package/API research verified independently against the npm registry (`npm view @base-ui/react version` → `1.6.0`; `npm view @base-ui-components/react version` → `1.0.0-rc.0`, confirming the legacy name) and against base-ui.com docs (Tabs, Slider, Popover, Toggle Group, Combobox, Button, composition handbook).
- **Scope:** the **primitive/behavior layer only** — `radix-ui` + `cmdk` → `@base-ui/react`, on the NH-254 catalog components (`Tabs`, `RangeSlider`, `Popover`, `ToggleChipGroup`, `FacetFilter`, `TokenPicker`, `Command`). Does **not** change: the fetch-agnostic contract (`options`/`value`/`onChange`/`shouldFilter`/`onQueryChange`/`loading`), the folder-per-component file set, the teal/gray token language, or `SearchInput`/`Pagination` (already native, untouched).

---

## Context

NH-189 picked Radix + shadcn-style wrappers as the design-system foundation (2026-06-25); NH-254 (PR #99) then hand-rolled a multi-select combobox (`FacetFilter`/`TokenPicker`) on top of `cmdk`'s `Command`, because Radix has no first-class combobox primitive. That hand-rolled assembly works (unit tests, a11y, VR all green) but carries real cost: chips, keyboard wiring (Enter-vs-remove-button conflicts, IME composition guards), and the `aria-controls`-must-always-resolve workaround are all bespoke code we own and maintain.

Base UI (base-ui.com) is the Radix-lineage successor and now ships a first-class `Combobox` with built-in multi-select (`Combobox.Chips`/`Chip`/`ChipRemove`) and consumer-controlled async filtering (`filteredItems` + `filter={null}` + `onInputValueChange`) — the exact shape `FacetFilter`/`TokenPicker` need, without owning the chip/keyboard plumbing ourselves. leocaseiro decided to consolidate on Base UI **now**, before NH-262 (11 primitives, PRs #101/#109/#112) and NH-264 (form components) land more Radix surface area — nothing is merged to master, so this is the cheapest point to redirect.

---

## Decision

Migrate the **primitive layer** of the NH-254 catalog components from `radix-ui` + `cmdk` to **`@base-ui/react` (current package name — not the legacy, now-superseded `@base-ui-components/react`, last published as `1.0.0-rc.0`)**, pinned to the latest stable **`1.6.0`**. Freeze the wider fleet (NH-262, NH-264) at their current Radix state and redirect future work to Base UI using the mapping below. `cmdk` is dropped entirely — Base UI's `Combobox` fully replaces the hand-rolled `Command` assembly.

### `cmdk` disposition

Dropped. Base UI's `Combobox` (multi-select + chips + `filteredItems`/`filter={null}`/`onInputValueChange`) covers the current hand-rolled use case, including the chip rendering `cmdk` left fully custom. `pnpm remove cmdk` once `Command`/`FacetFilter`/`TokenPicker` are migrated.

---

## Rationale

- **Combobox is the forcing function.** Radix has no combobox primitive; the `cmdk` assembly we wrote is real code we own (chips, IME-guarded Backspace, `aria-controls` keep-alive) that Base UI's `Combobox` gives us for free.
- **Cheapest time to switch.** Nothing is merged to master or in production; NH-262 (11 primitives) and NH-264 (forms) are still open PRs, not yet compounding the Radix surface area.
- **`render` vs `asChild` is a wash, not a regression** — Base UI's explicit `render` prop is the same composition idea as Radix's `Slot`, just spelled differently.
- **Popover's inline-by-default model is a genuine improvement** over the Radix workaround (render `Content` and skip `Portal`, rather than suppressing one).

---

## Consequences

**Positive:** deletes the entire `cmdk` dependency + the `Command` component folder; deletes the hand-written chip/keyboard-conflict code in `TokenPicker`; NH-268's `activateOnFocus`/`loopFocus` ask for `Tabs` is a first-class prop, not a workaround; `ToggleChipGroup`'s single-mode string↔array boundary conversion goes away (Base UI is array-always, matching our public API already).

**Negative / costs:**

- No built-in `loading` state on `Combobox` — `useTransition`/`aria-busy`/`Combobox.Status` wiring is new code to write and test.
- All VR baselines (darwin + Linux Playwright-container) must be regenerated — visuals change even where behavior doesn't.
- NH-262 (#101/#109/#112) and NH-264 sessions are frozen mid-flight and need a coordination note (see handoff below) rather than landing as-is.
- `Slider.Thumb` now requires an explicit `index` prop per thumb (was DOM-order-inferred) — a small, mechanical but easy-to-miss change.

---

## Alternatives considered

- **Stay on Radix + keep the hand-rolled `cmdk` combobox** — rejected: the chip/keyboard code is exactly the maintenance burden Base UI's `Combobox` removes, and the surface area only grows if NH-262/NH-264 land first.
- **Migrate later, after NH-262/NH-264 merge** — rejected: strictly more Radix surface area to re-migrate; today is the cheapest point (leocaseiro, 2026-07-07).
- **Legacy `@base-ui-components/react` package** — rejected: superseded at the Base UI v1.0.0 stable release (2025-12-11); the correct current package is `@base-ui/react`.

---

## Enforcement / follow-up

- **No machine enforcement** (library choice is prose-grade); `package.json`/`pnpm-lock.yaml` are the artifact-level record once `radix-ui`/`cmdk` are removed and `@base-ui/react` is added.
- Implementation tracked on PR #99 (NH-254) — this ADR's mapping is the reference for that migration.
- **Coordination note for the frozen fleet** (NH-262 #101/#109/#112, NH-264): redirect any further primitive work to `@base-ui/react` using the mapping table above; do not add new Radix (`radix-ui`) usage to those PRs. `Button`'s `Slot`→`render` swap is deferred — only do it if a frozen PR is blocked without it.
